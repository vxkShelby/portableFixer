# PortableFix GUI — Design/UX Audit

Scope: `portablefix/gui/main_window.py`, `portablefix/gui/style.py`, `portablefix/report.py`, `portablefix/i18n.py`, `Modules/*/actions.yaml` (labels only), plus brief supporting reads of `main.py`, `portablefix/executor.py`, `portablefix/restore_point.py`, `portablefix/settings.py` to verify claims. Read-only; no files modified.

Dataset used for quantified claims (from `Modules/*/actions.yaml`, 12 modules):
- **82 actions total.** Category split: DIAGNOSTICS 19, CLEANUP 26, **REPAIR 32**, SECURITY 5.
- Risk split: SAFE 47, **MODERATE 25**, DESTRUCTIVE 6, REQUIRES_REBOOT 4.
- Cleanup category alone: 13 MODERATE + 5 DESTRUCTIVE. Repair category alone: 11 MODERATE + 1 DESTRUCTIVE.

---

## Top 5

1. **[Critical] Every `QMessageBox` in the app renders in the stock light OS theme**, breaking the dark UI at the most safety-critical moments (risk confirmations). `portablefix/gui/style.py` has no `QMessageBox` rule anywhere in it, and the app never sets a `QApplication`-level stylesheet. Only two `setStyleSheet` calls exist in the whole codebase — `main_window.py:76` (the main window) and `main_window.py:253` (the batch-summary `QDialog`, styled deliberately). Every `QMessageBox.warning`/`.question` call site is left unstyled: `main_window.py:307, 391, 405, 415`, plus `main.py:27` and `main.py:35` (shown *before* the main window even appears).
2. **[Critical] Confirmation-dialog storm with no bulk override or cancel.** `_dispatch_action` (`main_window.py:403-422`) pops a blocking `QMessageBox` per MODERATE/DESTRUCTIVE action, serially, once per action in the queue. Worst case (select-all): up to **31 modal clicks** (25 MODERATE + 6 DESTRUCTIVE) in one run; 18 in Cleanup alone, 12 in Repair alone. There is no "apply to all," no "don't ask again this batch," and no way to abort a running batch — `run_button.setEnabled(False)` (`main_window.py:348`) is the only queue-level control; `ActionRunner` (`executor.py:27-64`) exposes no cancel/terminate hook at all.
3. **[Critical] The DRY-RUN toggle — the app's single safety-critical control — looks like every other checkbox and its state silently persists.** `style.py:96-113` styles `QCheckBox` generically; `dry_run_checkbox` (`main_window.py:99-102`) gets no distinct object name or visual treatment, so it's indistinguishable from an ordinary action checkbox. Its value is saved to `settings.json` and reloaded on next launch (`settings.py:11,28`; `main.py:51`), so turning it off once to do a real run makes *all future launches* start in live mode by default, with no strong visual cue that this is the state.
4. **[Important] Category cards flatten module identity at scale.** The REPAIR category (`main_window.py:161-206`) renders as **one card with 32 checkboxes from 5 different modules** (disk, integrity, windows-update, network, tuning) back-to-back with a single heading and zero sub-grouping (the nested loop at `main_window.py:188-204` never emits a per-module header). The HTML report *does* tag each action with its module (`report.py:129`, `.mod` span) — that information exists but is thrown away in the live selection screen.
5. **[Important] Batch-summary dialog has no scroll area and drops data it already computed.** `_show_batch_summary` (`main_window.py:250-291`) stacks one `QLabel` per result directly in a `QVBoxLayout` with no `QScrollArea` — a 20-30 action batch (Cleanup has 26 actions total) can make the dialog taller than the screen with the "Open report" button pushed off-screen. It also never shows the free-space before/after delta even though `_run_next` computes exactly that (`main_window.py:347, 357`) and hands it to `report.generate_report` — the HTML report renders it (`report.py:142-148`) but the in-app dialog does not.

## 1. Layout & hierarchy

| Sev | Where | Issue | Fix |
|---|---|---|---|
| Important | `main_window.py:161-206`, esp. 188-204 | One card per **category**, not per module. Actions from every module in that category are appended as a flat list of rows under a single `cardHeading`. At current content (REPAIR=32, CLEANUP=26 actions) this is a long undifferentiated wall of checkboxes. | Insert a lightweight sub-header row (small `QLabel`, muted color, e.g. module display name) each time `module` changes inside the loop at line 188, so REPAIR reads as 5 visually separated mini-sections instead of 32 flat rows. |
| Important | `main_window.py:77` (no corresponding `setMinimumSize` anywhere in the file) | `self.resize(1000, 700)` sets an initial size but no floor. With `category_list.setFixedWidth(190)` (line 123) and several Slovak labels 35-46 chars long (see §6), shrinking the window has nothing stopping the checkbox/badge row from clipping or overlapping — `QCheckBox` text doesn't wrap or elide. | Add `self.setMinimumSize(760, 480)` (or similar) in `_build_ui` right after `resize`. |
| Important | `main_window.py:250-291` | Batch summary dialog is unbounded height (see Top 5 #5). | Wrap the per-action rows in a `QScrollArea` with `setMaximumHeight(min(500, screen_height*0.7))` on the dialog, keep the button row outside the scroll area so it's always reachable. |
| Minor | `main_window.py:131-149` vs `173-184` | Two visually identical sets of "Select all / SAFE only / Clear selection" buttons exist: one global (acts on all 82 actions, line 136-147) and one per category card (acts on that category only, line 173-184). Both use the same `selectionBtn` object name/QSS, same text, same size — the only differentiator is the small `"All categories:"` label to the left of the global row. Easy to click the wrong scope, then run a much bigger batch (and dialog storm) than intended. | Visually demote or differentiate the global row, e.g. `border: none; color: #565f89;` with an icon, or move it into a menu/overflow rather than a full button row identical to the category-scoped one. |
| Minor | `main_window.py:227-229`, `_on_category_changed` | All 4 category cards are built once and shown/hidden via `setHidden`. This scales fine for 4 categories (not a perf problem), but it does mean the sidebar can never show a per-category action *count* or "N selected" badge, which would help orient the user before switching tabs — nothing in `category_list` items communicates how many actions or how many are currently checked in the hidden tabs. | Append a count to the `QListWidgetItem` text, e.g. `f"{name} ({selected}/{total})"`, refreshed on every checkbox toggle. |

| Sev | Where | Issue | Fix |
|---|---|---|---|
| Critical | `style.py` (whole file — no `QMessageBox` selector) | See Top 5 #1. | Add explicit rules, e.g.:<br>`QMessageBox { background-color: #1a1b26; }`<br>`QMessageBox QLabel { color: #c0caf5; }`<br>`QMessageBox QPushButton { background-color: #2f3549; color: #c0caf5; border-radius: 6px; padding: 6px 16px; min-width: 70px; }`<br>and call `msg_box.setStyleSheet(style.STYLE)` (or a shared helper) at every `QMessageBox.warning/question` call site instead of relying on the static convenience methods, in both `main_window.py` and `main.py`. |

| Important | `style.py:127-166` | No `:focus` state defined for `QPushButton` or `QCheckBox` anywhere in the sheet — keyboard-tab visibility across ~26-32 stacked checkboxes per category relies entirely on Qt's default focus rendering, which is easy to lose against the custom dark palette. | Add `QPushButton:focus, QCheckBox::indicator:focus { border: 2px solid #7aa2f7; }`. |
| Minor | `style.py:68-83` | Only `QScrollBar:vertical` is styled; no `QScrollBar:horizontal` rule. | Important | `main_window.py:89`, `i18n.py` (no `"admin"` key exists in either language table) | Admin-pill text is `"admin"` — a bare hardcoded literal, never passed through `self._t(...)` — while the non-admin state uses the fully translated `readonly_banner` sentence (`i18n.py:4,30`). | Minor | `style.py:115-125` | Risk badges rely on background color plus the risk **word itself** for meaning (good — not color-only), but nothing in the UI explains what SAFE/MODERATE/DESTRUCTIVE/REQUIRES_REBOOT actually mean (no legend, no tooltip on the badge). ## 5. Accessibility

| Sev | Where | Issue | Fix |
|---|---|---|---|
| Critical (measured) | `style.py:163-166` (`QLabel#selectionScope`) and `report.py:82,89,98,99` (`.meta`, `.lbl`, `.mod`, `.ts`) | Muted text color `#565f89` fails WCAG contrast everywhere it's used. Measured (WCAG relative-luminance formula): **`#565f89` on window bg `#1a1b26` = 2.76:1**; **on card/chip bg `#24283b` = 2.35:1**. Both are well under the 4.5:1 AA minimum for normal-size text (and the report's chip labels are only 11px, `report.py:89`). By contrast the rest of the palette is fine: main text `#c0caf5` on `#1a1b26` = 10.6:1, accent `#7aa2f7` = 6.8:1, all four risk-badge text/background pairs = 6.5-9.4:1. | Replace `#565f89` with something in the same hue that clears 4.5:1, e.g. **`#7f88b0` ≈ 4.5:1** (minimal palette change) or reuse the already-present `#a9b1d6` (8.1:1, already used for console/selection-button text) for consistency with an existing token rather than adding a new one. |
| Important | `style.py:96-113`, `40-59`, `127-148` | No explicit `:focus` styling for interactive controls (checkboxes, buttons, list items beyond `:selected`) — see §4. Keyboard-only operation is functionally possible (standard Qt tab order + native `QListWidget` arrow-key nav) but hard to *see*. | See §4 fixes. |
| Minor | `style.py:29-30,118-119,155` | Several text sizes sit at 8-9pt (`adminPill` 9pt bold, `riskBadge` 8pt, `selectionBtn` 8.5pt, `selectionScope` 9pt) with no in-app zoom/font-scale control. Fine for most users, tight for low-vision users on a diagnostic tool whose audience skews toward "something is already wrong with my PC." | Not urgent; if pursued, a simple `Ctrl+=/-` handler multiplying a base `QFont` size app-wide is a small, self-contained addition. |

## 8. HTML report vs. app design language

| Sev | Where | Issue | Fix |
|---|---|---|---|
| Minor/Important | `report.py:76-108` (`_CSS`), whole document | Report reuses the app's dark palette faithfully and consistently — `RISK_COLORS` in `style.py:3-8` and `_RISK_COLORS` in `report.py:68-74` are identical (plus a sensible `UNKNOWN` fallback). Good consistency, but the document has **no `@media print` rules and no `color-scheme` meta tag**. This is a real, plausible failure mode: a report meant to be "handed to someone" or printed for records will very likely render as near-invisible light-blue-on-transparent text once a browser's print engine drops background colors (common default), since all text colors (`#c0caf5`, `#565f89`, etc., `report.py:78-82`) assume the dark `body` background stays intact. | Add a minimal print stylesheet forcing dark text on white (or `-webkit-print-color-adjust: exact; print-color-adjust: exact;` on `body`/`.card` to force background preservation), and a `<meta name="color-scheme" content="dark">` tag for consistent browser chrome (scrollbar/frame) around the dark body. |
| Important (inherited) | `report.py:82,89,98,99` | Same `#565f89` contrast failure as §5, carried into a static artifact that may be viewed outside the app's controlled dark chrome (e.g., in a bright office, on a projector, screenshotted). | Same fix as §5. |
| Minor | `report.py:128` | Risk badge text in the report is the same untranslated raw enum as the live GUI (§6) — consistent with the app's own bug, at least, but still not localized. | Same fix as §6. |

## What already works well (brief, for calibration)

- Long-running commands run on a `QThread` (`executor.py:27`), so the UI never truly freezes even when feedback is missing — the *perception* of freezing (§3) is a feedback gap, not an actual hang.
- Risk badges encode risk via both color *and* text, not color alone — a real mitigation against pure colorblind confusion between SAFE (green) and DESTRUCTIVE (pink/red).
- The color palette itself, where it *is* applied, has strong contrast (6.5:1-10.6:1 measured for primary text, accent text, and all badge foreground/background pairs).
- Consistent, deliberate reuse of the same Tokyo Night tokens between `style.py` and `report.py` (identical risk colors, matching card/chip/badge vocabulary) — the report doesn't feel like a bolted-on afterthought design-wise, just incomplete in a couple of specific spots (contrast, print).
- Undo-script generation and restore-point creation before risky batches (`main_window.py:372-385`) is a genuinely good safety mechanic; it's the *feedback* around it that's missing, not the mechanic itself.
